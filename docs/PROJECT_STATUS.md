# Kitchen Companion: 現状と移行計画

更新日: 2026-10-09

## 結論

Home Assistant内の既存「調理アシスト」は残滓ではなく、稼働確認済みの移行元です。新Appを先に導入して
置き換えるのではなく、設定の保全、読み取り接続、並行検証、明示的な切り替えの順に進めます。

開発中のStage VMは実Home Assistantとは別VMであり、Home AssistantとMealieは存在しません。Stageでは
架空データとモックだけでUI・API契約を検証し、実環境のURLや認証情報を置かない方針です。

## 役割分担

| 構成要素 | 役割 | 正本 |
| --- | --- | --- |
| Mealie | 登録済みレシピ、材料、工程、出典 | レシピデータの正本 |
| Home Assistant | 工程状態、Echo読み上げ、Assist、買い物リスト連携 | 家庭内操作の正本 |
| Kitchen Companion | タブレットUI、検索、動画と工程の並列表示、保存前確認 | 表示・操作層 |
| SQLite | 下書き、キャッシュ、移行時の対応表 | 補助データのみ |

## 既存Home Assistant資産

別チャットで実環境を操作し、次の存在と一部動作が確認されています。実環境固有のURL、config entry ID、
Mealie recipe UUID・slugはこのGit管理文書には保存しません。

- ダッシュボード名: `調理アシスト`
- メインビュー: `/dashboard-cooking/cooking`
- レシピ一覧ビュー: `/dashboard-cooking/recipes`
- 選択中レシピのヘルパー: `input_text.cooking_recipe`
- 現在工程のヘルパー: `counter.cooking_step`
- 主工程スクリプト: alias `調理アシスト工程案内`（entity IDはGit管理外）
- 工程操作: `show`、`next`、`previous`、`start`
- 工程表示: 現状は`persistent_notification`へ出力
- Echo読み上げ: 既存のキッチン通知先で出力を確認済み（entity IDはGit管理外）
- 別の読み上げ専用スクリプトは存在する可能性があるが、entity IDは未確認
- Mealie連携の`get_recipe` actionで、名前、slug、材料、工程、元URLを取得可能
- Assist pipeline `料理アシスタント`で日本語テキスト対話を確認済み
- Androidブラウザのマイク入力は未確認。LAN内HTTPによる制限の可能性を含め、未診断

既存ダッシュボードでは、確認時点のMealieレシピ20件が固定ボタンとして登録されています。料理名から
選択して工程1を表示する動作は確認済みですが、新規レシピの自動反映、検索、ダッシュボード内の工程全文
表示は未実装です。

## 現在の試作App

このリポジトリには次のローカル機能があります。

- 写真付きレシピ一覧と検索
- 手入力、動画URL、schema.org Recipeページからの下書き作成
- 人数変更による分量計算
- タブレット向け工程表示、読み上げ、タイマー
- SQLiteへの下書き保存
- HA OS App用のIngress構成
- Stage専用の読み取り専用Mealieモックと、SQLite下書きをまとめた検索カタログ
- Stage専用のHA工程操作モック（開始・表示・次へ・前へ・読み上げ要求）
- UI上の実行モード表示と、実環境への外部書き込みを無効にした状態表示
- Mealieの一覧・詳細をGETだけで取得するクライアント契約と、HAの指定scriptだけを呼ぶクライアント契約
- tokenを応答や例外へ含めない共通JSON HTTP層（Stageでは記録型モックだけで検証）
- HA OSのSupervisor API tokenを自動利用し、Mealie tokenだけをGit管理外の読み取り専用設定から取得する構成
- `stage`を既定値とし、App設定で明示した場合だけ実環境クライアントを組み立てるfactory
- Mealie画像をAppが認証付きで取得し、tokenをブラウザへ渡さず同一オリジン配信する画像中継
- 画像のID・MIME type・8MB上限検証と、認証header転送を防ぐredirect拒否
- HA工程操作のrequest ID・永続状態により、完了済み応答を再利用し、結果不明時は自動再送を拒否

Stage VMから実HA・Mealieへは接続しません。次の実環境アダプターはまだ未実装です。

- Mealieのレシピ一覧・写真・検索の動的取得
- 選択レシピの材料・工程取得
- 既存HA工程スクリプトの呼び出し
- キッチンEchoへの読み上げ
- Mealieへの確認後保存
- Home Assistantの買い物リスト連携
- Assistとの会話文脈共有
- 動画字幕・テロップ抽出と出典照合

## 必須要件

1. Mealieレシピを料理名、写真、検索から選択し、slugやURLの手入力を不要にする。
2. タブレット上で動画のシークと現在工程を同時に操作できるようにする。
3. テキストと音声のどちらでも検索・工程操作できるようにする。
4. 取得したレシピや動画由来の内容には出典を表示する。
5. 出典にない分量・時間は推測せず、`未確認`と表示する。
6. 外部レシピ、動画字幕、テロップから抽出した内容は、ユーザー確認後にだけMealieへ保存する。
7. 材料をHome Assistantの買い物リストへ追加できるようにする。
8. 既存のキッチンEcho読み上げを維持し、将来はタスク完了などのアナウンスへ拡張できるようにする。
9. 一般知識による回答を、保存済みレシピや動画を取得した結果として表示しない。
10. 既存ソリューションを優先し、継続費用は低コストまたは定額を基本とする。

## 安全な移行手順

### 1. 保全

- Home Assistantのフルバックアップを作成する。
- `調理アシスト`ダッシュボードのRaw configurationをエクスポートする。
- 関係するスクリプトとヘルパーの設定をエクスポートする。
- Mealieのバックアップを作成する。
- 実環境固有値を保存する場合は、Git除外済みの`docs/local/`だけを使用する。

### 2. 読み取り統合

- 新AppからMealieの一覧・検索・詳細を読み取り専用で取得する。
- Mealieの既存20件と新UIの件数・名前・工程数を照合する。
- 外部ページの画像や動画をレシピの正本として扱わず、Mealieのデータと出典を区別する。

### 3. 操作統合

- 新Appの`開始・前へ・表示・次へ・読み上げ`を既存HA工程スクリプトへ接続する。
- `input_text.cooking_recipe`と`counter.cooking_step`が期待どおり更新されることを確認する。
- Echo読み上げは既存の確認済み通知先を利用し、別通知先へ勝手に切り替えない。

### 4. 書き込み統合

- 外部レシピや動画抽出結果を下書きとして表示する。
- 材料、分量、工程、出典をユーザーが確認した後だけMealieへ保存する。
- 保存結果が不明な場合は自動再送せず、Mealie側を照合する。

### 5. 切り替え

- Androidタブレットで検索、工程操作、復帰、Echo読み上げを並行検証する。
- 新旧UIが同じMealieレシピと工程を示すことを確認する。
- ユーザーが切り替えを承認するまで、既存ダッシュボード、スクリプト、ヘルパーを削除しない。

## 次の作業
